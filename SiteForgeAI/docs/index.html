SiteForge AI 1.0.0

Local-first Windows AI website builder for creating, editing, validating and deploying real HTML/CSS/JavaScript websites.

Important: SiteForge AI does not include an AI subscription. Add your own provider key in Settings. Keys are not embedded in the application or generated websites.

1. Installation

  1. Run SiteForgeAI-Setup.exe as a normal Windows user.
  2. Launch SiteForge AI from the Start Menu or desktop shortcut.
  3. Choose a local project folder and create or import a website.
  4. On first use, open Settings and configure an AI provider if AI generation is required.

2. Supported AI providers

The application supports OpenAI, Gemini, Claude and OpenRouter through BYOK. Select the provider, enter the model name and paste your key. The key is stored locally using the application secure store. Provider account fees, rate limits and terms are controlled by the provider.

3. Create a website

Open Create Website, provide a name, describe the website, select a template and choose a local project folder. SiteForge AI creates real files including index.html, style.css, script.js, SEO metadata, sitemap.xml, robots.txt and favicon assets.

4. Direct visual AI editing

  1. Open a project in Live Preview.
  2. Click an element to capture its selector.
  3. Describe the requested change, for example: “Change this button to blue with rounded corners.”
  4. Press Ask AI to generate a structured proposal.
  5. Review the proposal and press Apply Changes.

Before applying a change, SiteForge AI creates a local version. Applied changes are written to the real project files. Use Undo and Redo to restore reviewed versions.

5. Import and repair

Import a website from a folder or ZIP. ZIP extraction is restricted to the selected destination. Use AI Repair to scan links, assets, metadata and project structure. Review the proposed diff before applying any repair.

6. Validate and deploy

Run Validation before publishing. Deployment supports SFTP, FTP, FTPS, cPanel and DirectAdmin when valid credentials and API details are provided. The recommended flow is:

Validate → Review Deployment Diff → Create Backup → Confirm Upload → HTTP Verify.

Remote deletion is never performed automatically without explicit confirmation. Keep a backup before every update.

7. Troubleshooting

ProblemAction
AI request failsCheck provider, model, key, internet connection and provider limits.
Preview is blankOpen or create a project containing index.html, then press Refresh.
Upload failsVerify host, port, protocol, credentials and remote path. Test with a small project first.
Installer does not startUse the x64 Windows build, reinstall to a user-writable directory, and check Windows Defender logs.

8. Data and privacy

Project files and credentials are stored locally unless the user requests an AI operation or remote deployment. For AI requests, selected project context may be sent to the configured provider. See PRIVACY_POLICY.html for the complete data-flow statement.

9. Support

Before requesting support, include the application version, Windows version, provider/protocol used, exact error message, and reproduction steps. Never include API keys, passwords or private website files.

10. Uninstall

Uninstall from Windows Apps. User data and project folders are not automatically deleted. Remove them manually only after confirming that backups are no longer needed.
